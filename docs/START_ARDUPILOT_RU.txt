ЗАПУСК ARDUPILOT / ПЛАНЕР / ROS 2
================================
Все команды ниже выполнять в Ubuntu-24.04 (WSL), не в PowerShell.
Рабочая папка: /home/nikol/autopilot

1. Демонстрационный полет с обычным армированием (терминал 1):
cd /home/nikol/autopilot
bash src/glider_visual_nav/tools/demo.sh flight 90

2. Пока идет подготовка/полет, окно Gazebo (терминал 2):
cd /home/nikol/autopilot
bash src/glider_visual_nav/tools/demo.sh gui

3. Дашборд с камерой, маршрутом и графиками (терминал 3):
cd /home/nikol/autopilot
bash src/glider_visual_nav/tools/demo.sh dashboard

4. Показать модель в Gazebo (терминал 4):
cd /home/nikol/autopilot
bash src/glider_visual_nav/tools/demo.sh focus

Автотест сам ожидает датчики, запрашивает GUIDED и штатное arming,
освобождает планер с испытательного крепления на высоте 145 м и
задает начальную скорость 16 м/с. Это воздушный старт. Подготовка
занимает время до начала 90 секунд измеряемого полета.
Результат сохраняется в log_visual_nav/demo_guided_<дата>.json.
По окончании теста сервер и узлы останавливаются. Открытые окна
могут оставаться с последним кадром; это не работающая камера.
Для повторения снова выполнить шаг 1. GUI/дашборд при необходимости
закрыть и открыть заново в шагах 2 и 3.

Режим без полета, для осмотра модели и датчиков:
bash src/glider_visual_nav/tools/demo.sh start
bash src/glider_visual_nav/tools/demo.sh gui
bash src/glider_visual_nav/tools/demo.sh dashboard
bash src/glider_visual_nav/tools/demo.sh status
Остановка:
bash src/glider_visual_nav/tools/demo.sh stop

Не запускать start одновременно с flight: это два владельца стенда.
start оставляет аппарат на креплении и сам не армирует.
Старый PX4: demo.sh px4 start (отдельная сборка с BUILD_PX4_INTERFACE=ON).

ЧТО ПОКАЗАТЬ РУКОВОДИТЕЛЮ
Карта: заданный маршрут, оценка положения, отдельный эталон Gazebo.
Камера: текстура и рабочие треки оптического потока.
Графики: оценка/эталон скорости и курса, ошибка XY, поперечная ошибка,
крен и команды управления. Наличие сигнала не означает его точность.
Эталон Gazebo НЕ передается навигации или автопилоту как измерение.

ЧЕСТНЫЙ СТАТУС
ArduPlane 4.6.3 + два документированных патча SITL; GUIDED/обычное arming
и полеты подтверждены, 26 тестов проходят. Критерии точности оценки на идеальном стенде пройдены.
Это не подтверждает аппаратную точность или универсальную точность
удержания маршрута. Чистый MAVLink-сенсорный режим экспериментальный.
Аппаратные компоненты подобраны как кандидаты; испытаний на железе нет.

МАРШРУТ
src/glider_visual_nav/config/arduplane_navigation.yaml
Менять пары XY в метрах ENU (X восток, Y север), затем перезапустить
стенд. Это локальная система с произвольным началом XY, не GPS.
