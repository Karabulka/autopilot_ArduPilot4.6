ДЕМОНСТРАЦИЯ GLIDER VISUAL NAV — GAZEBO / ROS 2 / PX4
Дата: 22.10.2026

НОВОЕ: start теперь автоматически открывает окно контроля полета.
ДОБАВЛЕНЫ ЖИВЫЕ ГРАФИКИ: переключайте вкладки вверху окна.
«Наведение» — курс LOS / навигации / Gazebo, поперечная ошибка, крен и высота.
«Точность» — ошибки Vx/Vy, магнитного курса, дрейф XY и скорость.
Общая шкала времени симуляции; выбор последних 30/60/120/300 секунд.
Пунктир →N — новая цель ППМ N (первый пунктир — первая известная цель).
Пауза графиков не останавливает самолет и запись телеметрии.
Наведение мыши на график показывает ближайшие значения.
Кнопка «Сохранить отчет: JSON + CSV + PNG» сохраняет метрики, данные графиков
и три снимка вкладок в /home/nikol/autopilot/log_visual_nav/.
У курса ENU 0° — восток, +90° — север. На переходе через ±180° линия разрывается.
При смене участка скачок e⊥ возможен из-за смены опорной прямой, а не координат.
Открыть это окно отдельно / повторно после закрытия:

bash /home/nikol/autopilot/src/glider_visual_nav/tools/demo.sh dashboard

В окне: маршрут, движущаяся точка, траектории навигации и Gazebo, камера,
желаемый курс LOS, фактический курс движения, магнитный курс носа,
высота, крен, скорость и независимые метрики ошибок.
Желтый — маршрут и желаемый курс; голубой — оценка навигации;
оранжевый — эталон Gazebo, исключительно для проверки.
Белый участок — текущая цель LOS. Углы ENU: 0° восток, +90° север.
До fly самолет неподвижен — направление движения не определено, показано «—».
На смене участка ошибка желаемого курса временно растет: самолету нужен вираж.
После поворота должно наблюдаться уменьшение угловой и поперечной ошибки.
Контроль работоспособности: ACTIVE, свежие данные навигации/камеры/эталона,
прохождение 3–4 участков, отсутствие неограниченного роста ошибки и высоты,
близость голубой и оранжевой траекторий. Это наблюдения, не автоматический допуск.
Для чистого интервала оценки нажать «Новый интервал измерений» перед fly.
Кнопка «Сохранить JSON» сохраняет итоговые метрики; сырые сопоставленные данные
автоматически пишутся в /home/nikol/autopilot/log_visual_nav/dashboard_*.jsonl.
JSON автоматически сохраняется при закрытии окна. Закрытие окна не останавливает
полет. Метрики относятся к периоду наблюдения, а не ко всему полету.
Сопоставление по меткам времени, без экстраполяции, с совмещением начального XY.
Сброс интервала также начинает новое совмещение XY; предыдущий результат сохранен.
Ground truth не публикуется в управление; окно не отправляет команд самолету.

Все команды ниже выполнять в Ubuntu 24.04 WSL, НЕ в PowerShell.
Открыть Ubuntu из меню Пуск. Из PowerShell сначала: wsl -d Ubuntu-24.04
Команды копировать отдельно, без приглашения командной строки.

1. ЗАПУСК СТЕНДА

bash /home/nikol/autopilot/src/glider_visual_nav/tools/demo.sh start

Подождать 20–40 секунд. Запуск выполняется в фоне и переживает закрытие
терминала. Не запускайте одновременно второй flight.launch.py.
Для проверки:

bash /home/nikol/autopilot/src/glider_visual_nav/tools/demo.sh status

Ожидается data: ACTIVE и число 640 (ширина полученного кадра).
Если стенд уже запущен данным скриптом, start повторно его не запускает.
Если найден ранее запущенный вручную сервер, скрипт попросит остановить его.
Вернитесь в терминал старого ros2 launch и нажмите Ctrl+C; затем повторите start.

2. ОКНО GAZEBO

Подождать загрузки сцены. Самолет изначально находится на высоте около 40 м,
поэтому с начального наземного ракурса его может быть не видно.
Перевести вид к самолету:

Включить сопровождение:

Если команда не сработала, дождитесь загрузки сцены и повторите ее.
Альтернатива: Entity Tree -> rc_cessna_visual -> контекстное меню Move To / Follow.
Для повторного открытия закрытого окна снова выполните gui, затем focus.

3. ОКНО КАМЕРЫ

4. НАЧАЛО ПОЛЕТА

Самолет до команды удерживается на стартовой высоте испытательным креплением.
Только ПОСЛЕ появления ACTIVE выполнить один раз:

Ожидаемый ответ data: true. Это воздушный старт со скоростью 16 м/с.
Разбег, взлет с полосы и посадка в данном сценарии не реализованы.
Начальная скорость задается однократно. Далее работает замкнутый контур.
Повторное открытие окон не перезапускает полет и не требует команды fly.
Для нового полета: stop, подождать 10 секунд, start, status, затем fly.

7. ЧТО ОБЪЯСНИТЬ НАУЧНОМУ РУКОВОДИТЕЛЮ

Камера смотрит вниз, верх изображения направлен к носу самолета.
Shi–Tomasi находит углы; Lucas–Kanade отслеживает их между кадрами.
Forward-backward проверка и RANSAC отбрасывают ошибочные треки.
Калибровка камеры и текущая высота переводят пиксельный поток в м/с.
IMU компенсирует вращение и наклон камеры на виражах.
Магнитометр с компенсацией наклона и склонения дает курс.
Скорость преобразуется в ENU и интегрируется трапециями в локальные координаты.
LOS преобразует ошибку маршрута в заданный крен; высота регулируется тангажом,
скорость — тягой. PX4 получает уставки через Offboard с преобразованием ENU/FLU
в NED/FRD. При потере визуальной навигации предусмотрен аварийный режим.
GPS отключен. Ground truth разрешен только отдельному оценщику ошибок.

Рабочая демонстрация: cruise_const_alt, маршрут из четырех участков,
высота оптического центра около 40 м. Неподвижный кадр до fly — норма.

Подтвержденные предыдущими испытаниями результаты, НЕ метрики текущего запуска:
45 секунд крейсерского полета, 4 участка; RMSE Vx/Vy 0.071/0.121 м/с;
RMSE курса 1.07 градуса; конечный дрейф 6.50 м (1.23% пути);
RMSE поперечной ошибки 11.94 м. Это исследовательский прототип SITL.
